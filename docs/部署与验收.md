# 本地部署与验收

本次目标是可复现的 Windows 本地演示。所有 HTTP 服务绑定 127.0.0.1；数据库容器属于 listening-integration，与其他 Docker 项目隔离。不是生产部署模板。

## 环境与启动

全部运行源码位于智能听书目录，Java 在 backend/java，H5 在 frontend/uniapp，Python 服务在 python，初始 SQL、知识资料和音频均已收进本目录。只需本项目目录，无须旁边的工程目录。需要 Docker Desktop、JDK 17、Maven、Node/npm、Python 3.12+。Java 内存受限为 192MB 堆，Node 构建为 512MB，Maven 默认为 256MB，便于当前机器同时启动三个 Java 服务。

```powershell
cd D:\code\python\AI_tingshu
.\scripts\dev\Doctor.ps1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements/requirements.lock.txt
.\Start.ps1 -UseLlm -WithKnowledge -WithOperations
```

首次启动会导入初始化 SQL 并构建 Java 与 H5；后续使用 `-SkipBuild` 复用构建。Java jar 在 Windows 运行时被锁定，修改 Java 后先 `.\Stop.ps1`，再执行不带 SkipBuild 的启动。只修改 Python 时也需要重启相应进程；管理页面模型配置保存后新请求立即生效，不需要重启。

服务端口：用户 18201、内容 18202、订单 18204、助手 18083、知识 18084、问数 18085。用户前端 `/listen/`，管理台 `/admin`。Docker 内持久化 MySQL、Redis、MongoDB；本地 `.runtime` 保存会话、向量缓存、查询审计、日志和私有凭据。不要公开整个 runtime 或把它提交到仓库。

## 迁移与恢复

新增 SQL 按文件名记录在 listening_ops.schema_migration，保存校验和与执行时间。已执行文件不可修改，应新增迁移文件；重启不会重复执行角色授权迁移。MySQL DDL 不保证整个文件原子性，因此建表使用 IF NOT EXISTS，种子使用 INSERT IGNORE，文件完整成功后才写迁移登记，允许中途失败后继续。

Stop.ps1 只停止登记且命令身份匹配的项目进程，停止本项目容器并保留卷。不要通过删除卷恢复环境，否则会丢失测试数据。退款 PROCESSING 租约、回执与审计都在数据库，重启后自动继续；不会通过 Redis 或模型历史决定支付结果。

DPAPI 模型密钥绑定当前 Windows 用户，不能跨用户直接复制配置。换机器请在管理台重新填写供应商密钥。本地支付回调密钥在 runtime 中随机初始化，丢失后需要检查并重新配置当前进程，不能把它硬编码到前端。

## 验收

```powershell
.\scripts\dev\VerifyAll.ps1                  # 单测与健康检查
.\scripts\dev\VerifyAll.ps1 -Live            # 加真实模型、召回、Agent与本地交易重启验收
```

Live 会产生供应商 API 用量，只新增明确标记的本地测试账号与订单，不进行真实资金操作。退款重试上限测试仅对它自己创建的任务缩短等待时间；恢复验收会实际重启本项目订单服务。正常产品仍使用原定重试间隔。

| 报告 | 作用 |
| --- | --- |
| `.runtime/java-payments-tests.log` | Java事务、回调、租约与重试单测 |
| `.runtime/verify-all-final.log` | 已实际执行统一验收入口：Python99、Java36和健康检查 |
| `.runtime/payments-acceptance.json` | 实际MySQL并发、回调与订单服务重启 |
| `.runtime/retrieval-evaluation.json` | 固定 Top-5 召回集 |
| `.runtime/agent-evaluation.json` | 工具选择、拒答、多轮、逐字引用与问数边界 |
| `.runtime/model-compatibility-live.json` | 当前保存供应商的真实连接与业务入口 |

AI POST 请求默认单实例最多并发 4 个、每令牌每分钟 30 次、总处理上限 120 秒。拒绝过载返回 429 和 Retry-After；超时返回 504，不保存未完成对话。限流在当前进程内存中，重启清空，不能描述为分布式限流。模型和服务错误保持明确提示，不进行自动扣费重试。

响应带 x-request-id，Python 转发到 Java 与内部知识、问数服务；运行日志只记录服务名、方法、路由模板、状态与耗时，不记录 token、密钥、请求正文或提示词。问数审计另行保存授权查询的 SQL 与口径。故障时先凭请求编号定位，再检查健康、数据库、模型供应商连接和错误提示。
